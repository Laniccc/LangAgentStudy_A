# 需求 → Agent 实现工作流

本文档定义你与「智能体搭建助手」协作时的标准流程。每次提出新需求时，按此模板沟通，助手会**先给出方案与讲解，再在 `agent_framework` 上同步改代码**。

---

## 1. 你如何描述需求（建议格式）

```markdown
## 目标
一句话说明 Agent 要帮用户完成什么。

## 输入 / 输出
- 输入：用户说什么、什么格式的文件/数据
- 输出：文本、结构化 JSON、文件、多轮对话等

## 能力边界
- 必须能做：
- 不必做：

## 约束（可选）
- 模型、延迟、成本、是否必须本地工具
- 是否需要记忆、多 Agent、人工确认
```

将填好的内容发给助手即可；也可直接自然语言描述，助手会帮你整理成上表。

---

## 2. 助手如何选型（常见 Agent 模式）

| 模式 | 适用场景 | 在本框架中的落点 |
|------|----------|------------------|
| **ReAct**（当前默认） | 需要查资料、算数、调 API，边想边用工具 | `graph.py`：`agent` ↔ `tools` 循环 |
| **纯对话** | 只聊天、无工具 | 去掉 `ToolNode`，单节点 LLM |
| **Plan-and-Execute** | 先拆步骤再逐步执行 | 增加 `planner` 节点 + `executor` 子图 |
| **Router** | 多类任务走不同子 Agent | `conditional_edges` 按意图路由 |
| **Human-in-the-loop** | 敏感操作需人工批准 | `interrupt_before` / 审批节点 |
| **RAG** | 基于私有文档问答 | 新增 `retrieve` 工具或节点 |

当前仓库已实现 **ReAct**；其余模式在需求明确时按需扩展 `graph.py` / `nodes.py` / `tools.py`。

---

## 3. 本仓库分层（实现时改哪里）

```
用户输入 (main.py)
    ↓
StateGraph(AgentState)     ← state.py：消息列表
    ↓
agent 节点                 ← nodes.py：SystemPrompt + LLM.bind_tools
    ↓ tools_condition
tools 节点 (ToolNode)      ← tools.py：@tool 注册
    ↓ 循环直到无 tool_calls
END → 最后一条 AIMessage
```

| 文件 | 职责 |
|------|------|
| `config.py` | API、模型、系统提示词 |
| `llm.py` | 创建 ChatOpenAI |
| `state.py` | 图状态（通常只有 `messages`） |
| `nodes.py` | 自定义节点逻辑 |
| `tools.py` | 工具定义与 `get_tools()` |
| `graph.py` | 拓扑：边、条件分支、编译 |
| `main.py` | CLI / 服务入口 |

---

## 4. 单次需求的交付物

每次实现后，助手会提供：

1. **需求整理**：目标、边界、选用的 Agent 模式  
2. **方案讲解**：图结构、状态、工具、提示词要点（含 mermaid 示意）  
3. **代码变更**：对应文件的最小 diff  
4. **验证方式**：如何 `python main.py` 或调用 `create_agent().invoke(...)`

---

## 5. 示例：在现有 ReAct 上增加工具

**需求**：Agent 能查天气（示例）。

**方案**：ReAct + 新 `@tool`，无需改图拓扑。

**实现步骤**：

1. 在 `tools.py` 增加 `get_weather(city: str)` 并加入 `DEFAULT_TOOLS`  
2. 在 docstring 中写清参数含义（供 LLM 选工具）  
3. 运行 `main.py` 问：「北京现在天气怎么样？」
